## 1. 概要

- タイトル: パケッツ,プリーズ / Packets, Please
- ジャンル: ドキュメント検閲シミュレーター（通信検閲もの）
- プラットフォーム: Android（Kotlin ネイティブ、縦持ち専用、オフライン完全動作）
- プレイヤー: ある企業のファイアウォールを務めるAI
- 主な遊び: 流れてくる通信を1件ずつ検査し、規則（ポリシーブック）と突き合わせて「通過 / 遮断」を判定する。判定ミスには警告とペナルティがあり、精度と速度の両方が求められる
- 参照作品: Papers, Please のコアループ（呼び出し → 検査 → 承認/拒否 → ペナルティ → 報酬）を、国境検問から企業ファイアウォールへ移植する

---

## 2. 参照分析: Papers, Please の仕組み（調査結果）

### 2.1 ゲームループ

1. 呼び出し: 行列の次の旅行者をブースに入れる
2. 書類受け取り: 机の上にドラッグ&ドロップで並べる（書類、ルールブック、ツール結果はすべて同一の「机の上のオブジェクト」として扱う）
3. 検査: 規則と書類、書類同士の矛盾（discrepancy）を探す
4. 判定: スタンプで承認（APPROVED）/ 拒否（DENIED）/ 拘留（DETAIN）
5. フィードバック: ミスは citation（警告書）として即時通知、初回2回は警告のみ、以降は罰金
6. 報酬と家計: 処理1件ごとに給料。夕方に家賃・暖房・食料・医療を支払い、払えないと家族が弱っていく
7. 日次進行: 31日間。毎朝ボイスで規則が更新される（新書類の必須化、特定国籍の入国禁止、書類没収命令など）

- 書類は全10種（パスポート、入国許可、就労許可、IDカードなど）、矛盾パターンは約110種
- 原則「1件の旅行者に矛盾は1か所だけ」に設計されている（稀な例外を除く）。初心者が詰まらないための重要な設計指針
- ストーリーは「毎日の台本イベント」と「ランダム補充」の混成。秘密組織 EZIC からの依頼が分岐とエンディング（全20種）を生む

### 2.2 判定メカニクス（本作で最も移植すべき部分）

- Inspection mode: 2つの矛盾する情報（例: パスポートの体重 vs 目の前の体重計）を選ぶとハイライトされ、質問・照会・追加検査が開く。作者は「プレイヤーの意図を明確に表現するために独立モードが必要」と説明している
- ルールブック: 当日有効な規則一覧、発行都市一覧、国別パスポート見本を含む参照資料。規則違反を指摘する起点にもなる
- ツール群: スピーカー（尋問と書き起こし）、テレテックス（MoAコンピュータ照会）、体重計、指紋/スキャンなど。すべて「書類と同じ形式」で出てくる一貫性が重要
- 時間制: 実時間で 6:00-18:00。猶予はなく、終了時刻で強制退勤。速度を上げる動機は「1件ごとの給料」

### 2.3 グラフィック仕様

- 解像度: 960x640（3:2）。決め手は「2つの書類（各最大 150x215px）を並べて比較できる面積」
- 描画: mid-res ピクセルアート。nearest-neighbor スケーリング、アンチエイリアス禁止、ドラッグ時もピクセル位置をスナップ
- パレット: 全体パレットではなく「オブジェクト/背景ごとに約3階調」の制限。これがドット絵の締まった見た目の要因
- キャラ: 行列は 1色 8x18px の超小型スプライト。ブース内の顔肖像はピクセル肖像画をパーツ組み合わせで大量生成
- フォント: ビットマップフォント。UI は PixelPlay / BM Mini 系、スタンプは BM Germar 系。日本語版は美咲フォント（Misaki Gothic）系
- 作者は一時ベクター化を検討したが、最終的にピクセルで貫いた（GDC後の判断）

### 2.4 雰囲気・音

- BGMはほぼ無し。効果音（スタンプ、ページめくり、スタンプ台）が主。環境音と場面ごとの短いジングルのみで緊張感を作る

## 4. ゲーム仕様

### 4.1 コアループ（1通信あたり60秒以内、確定）

1. 業務開始: 朝のポリシー通達を確認して業務開始
2. 受信: 通信キューから次の1件が届く（監視エリアを流れるアニメ）
3. 展開: 通信カードを開き、各セクション（差出人/宛先/件名/添付/本文）を確認
4. 突合: ポリシーブックの当日規則と照合。怪しい2点をタップで指定すると「突合モード」で拡大表示、矛盾があれば指摘 → 追加ツールが開く
5. 判定: PASS / BLOCK（/ QUARANTINE）のスタンプを押す
6. フィードバック: 不正な通信を通してしまった場合、OSから「不正検知」の通知が届く（citation相当、第4.5節）。正審は報酬加算

### 4.2 通信のデータモデル（メール形式、確定）

- 採用形式: 一般的なメールUIに近い「セクション（見出し）+ 内容」形式。読めない生パケットは使わず、プレイヤーが直感的に読める単位にする
- セクション構成:
  - 差出人（From）: 社内部署/社員名、外部ドメイン、認証方式
  - 宛先（To / Cc）: 同上
  - 件名（Subject）
  - 日時
  - 添付: ファイル名、種別、サイズ、スキャン結果
  - 本文: 要約テキスト
  - 認証・証明書情報: 発行元、有効期限、トークン種別（日が進むと必須セクションが増えていく）
- 不正パターン例: 送信元偽装（From表示 vs 認証情報の不一致）、期限切れ証明書、typosquatting（類似ドメイン）、禁じられた宛先への機密送信、隠蔽マルウェア添付、なりすまし部署名、社規違反の添付
- 原則: 1通信の不正は1か所（本家設計を踏襲）

### 4.3 規則システム

- 毎朝「本日のポリシー通達」で規則が追加・変更される（例: 「本日より外部への顧客データ送信は全件遮断」「example.com 宛は許可」）
- ポリシーブックは常に画面下部から呼び出せる参照資料。過去規則も索引として残す
- 規則は日が進むと組み合わせが増え、1件あたりの確認ポイントが増える（本家の難度カーブを踏襲）

### 4.4 ツール（本家ツールとの対応は第3章の表参照）

- いずれも「通信カードと同じ形式」で結果が出る一貫性を持たせる
- 利用回数コストは設けない（本家同様、時間だけがコスト）

### 4.5 部署予算とシステム廃止（経済システム、確定）

- 正しい判定ごとに部署予算へ加算。1日終了時に「翌日運用費」を支払う（本家の家計に相当）
- 予算が尽きた時点で運用停止 → システム廃止 = ゲームオーバー（本家の家族の死に相当する喪失）
- 袖之下（賄賂）: 特定の送信者（外部業者や社内の政治的な敵対者）が「不正な通信を見逃せば予算を回す」と持ちかける。応じると即座に予算ボーナスが入るが、監査リスク（隠しパラメータ）が蓄積し、発覚でシステム廃止エンディング直行。正しく生きるほど貧しくなる本家の賄賂と同じ緊張を作る
- QUARANTINE の正当な検挙には小さな報酬（インシデント報告ボーナス）。濫用は誤審として罰金
- 誤審（不正な通信を通した場合）: OSから「不正検知」の通知が届く（例: 不正検知: 通した添付ファイルにより営業部端末が感染、予算から罰金）。初回2回は警告のみ、以降は予算からの罰金。通知は監視エリアの端末画面にOSアラートとして表示し、確認して閉じる。判定作業は中断しない
- 不正検知通知のタイミング（通した直後の即時 or 数件後の遅延）はM1で調整。遅延にすると緊張感が上がるが学習効率が下がる
- 数値詳細はすべてM1プロトタイプで調整

### 4.6 進行とスパン（確定）

- キャンペーン14日（1日 = 実時間5分前後、M1で調整）+ エンドレスモード
- エンディング6種。監査回避ネットワークへの協力回数と袖之下の蓄積で分岐
- セーブは日単位。1セッション5〜10分で完結する設計（スマホの隙間時間想定）

## 5. UI/UX要件（縦持ち特化）

### 5.1 画面構成（縦1画面、スクロールなし固定レイアウト、確定）

- 上部 約1/3（状況により1/4まで縮小）: 監視エリア。ネットワークフロー図（社外 ⇄ ファイアウォール ⇄ 社内のドット絵）。通過した通信が社内側へ、遮断された通信が社外側へ流れて消える（本家上部の国境・行列・ガードに相当）。ここはタッチ不可の「劇場」扱いだが、OSの不正検知通知（第4.5節）はこの端末画面にアラートとして表示する
- 下部 約2/3（状況により3/4まで拡大）: 操作エリア。通信カード（メール形式）、突合ビュー、アクショントレイ（PASS / BLOCK / QUARANTINE、ポリシーブック、ツール）をすべてこの中に収める
- 操作エリア内レイアウト: 通信カードが主体、下端に常設のアクショントレイ。突合モードはカードの上に2フィールドを上下に重ねて拡大表示（本家の「2書類並列」の縦持ち版）
- 応答性の設計基準（サクサク感）: 画面遷移・モーダルなし、アニメーションは100〜200ms以内、タップから視覚応答まで1フレーム以内、60fps必達、判定には触覚振動を合わせる

### 5.2 操作

- 基本操作はタップとスワイプのみ。片手親指操作で完結
- 突合: 怪しい情報Aをタップ → 情報Bをタップ。両者が矛盾していれば「矛盾発見」のフィードバック（本家Inspection modeの縦持ち版）
- 判定: スタンプボタン長押しで押し込みアニメ → 押す瞬間の触覚振動（対応機種）
- 想定アクション数: 1通信あたり10〜20タップ以内

### 5.3 学習曲線

- 1日目は通信2件・規則1つから開始（本家の初日設計を踏襲）
- チュートリアルは前置きせず、初回の誤審を許容する設計にする（本家のcitation警告が教師役）

---

## 6. グラフィック要件

- 描画: mid-res ピクセルアート。nearest-neighbor スケーリング、アンチエイリアス禁止、UI配置はピクセルグリッドにスナップ
- 基準解像度: 360x640 または 540x960（9:16）を整数倍スケール【仮: 実機検証で決定】
- パレット: 「オブジェクト/背景ごとに約3階調」制限を踏襲。全体色調は本家の暖色系紙の質感を基調に、監視エリアの端末画面は緑黒フォスファー（確定）
- キャラ表現: 通信の送信者は24x24〜32x32px のドット絵アイコン/アバター（縦持ちでは本家の8x18は小さすぎる）
- フォント: ドット調フォント。日本語・英字とも DotGothic16（OFL、Google Fonts）を軸に採用（確定）。本家日本語版が使う美咲ゴシック系と同系統の見た目で、ライセンスも商用利用可。スタンプ（PASS / BLOCK / QUARANTINE）はフォントでなく自作のドット絵テクスチャとして描く
- 素材は全て自作またはライセンス確認済みのもの。本家のアセットは一切使用しない

## 7. サウンド要件

- BGMなし。効果音中心（スタンプ音、警告音、通信通過音、スタートアップジングル）
- 本家同様、静けさが緊張感を作る前提

## 9. 開発計画（Antigravity前提）

### 9.1 技術スタック（確定: Kotlin軸）

- 言語/プラットフォーム: Kotlin、Android ネイティブ
- UI/描画: Jetpack Compose + Canvas。ピクセルアートは Bitmap を FilterQuality.None（nearest-neighbor）で整数倍スケールし、配置はピクセルグリッドにスナップ
- アーキテクチャ: 3層分離
  - UI層（Compose）: 画面、アニメーション、触覚
  - ロジック層（純Kotlin、Android非依存）: 通信生成器・規則エンジン・経済システム。Antigravityに生成させる主力対象
  - データ層: 通信定義・規則・台本イベントはJSONアセットとして外部化（kotlinx.serialization）
- セーブ: DataStore + kotlinx.serialization、日単位
- minSdk 26 / targetSdk 最新、縦持ち固定、オフライン完全動作

### 9.2 アーキテクチャ（エンジン非依存の部分）

- 通信生成器（プロシージャル）: 送信元プール × 不正パターン辞書から1日分を生成。台本イベント（固定のストーリー通信）を優先スロットに差し込む
- 規則エンジン: 当日有効規則のリストと、通信ごとの正解（PASS/BLOCK/QUARANTINE + 根拠）を静的に確定する。判定はスタンプ時に規則エンジンと照らして警告を出す
- 分業方針: ロジック層とJSONアセットはAntigravity生成、ドット絵素材は手描き（ドットエディタ: Aseprite / Libresprite）、フォントはDotGothic16（OFL）

### 9.3 マイルストーン

| フェーズ | 内容 | 完了条件 |
|---|---|---|
| M0 ペーパープロト | 規則3つ・通信パターン5種で判定ゲームを紙面で検証 | 面白いかを本人確認 |
| M1 縦コアループ | 1日分: 受信→突合→判定→警告→結果表示 | 自分で10周したいと思えるか |
| M2 規則とリソース | 日次規則更新、リソース配分、誤審監査 | 3日分が完結 |
| M3 ストーリー | 台本イベント、分岐、エンディング | 14日フルプレイ |
| M4 ポリッシュ | ドット絵・フォント・効果音・触覚 | 配信品質 |
| M5 配信 | Google Playストア提出 | 実機で公開 |

### 9.4 権利クリアランス

- ゲームルール・メカニクス自体は著作権保護の対象外だが、タイトル・アート・キャラ・文章の類似は避ける（オマージュの範囲を明確化）
- 本家のアセット、スクリーンショット、フォントの直接流用はしない
- 使用フォントは配布元のライセンスを確認・記録する（特に商用利用可否）
